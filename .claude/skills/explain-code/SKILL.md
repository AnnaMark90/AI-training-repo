# Объяснение кода

Цель — чтобы новичок в проекте быстро понял, **как устроена и зачем так сделана** эта часть кода. Ответ краткий и по делу. Читатель знает Playwright и TypeScript: термины (`storageState`, fixture, project, Page Object) не поясняются, база языка не разжёвывается.

Тема: `$ARGUMENTS`. Если тема не указана — спроси, что разобрать, и остановись.

Скилл только читает и объясняет. Файлы проекта не изменяются.

## Шаг 1. Изучить код

1. Найди точки входа: файл, указанный пользователем, или место, где тема начинается (конфиг, entry-файл, тест). Для темы словами найди её через Grep по именам, конфигу и импортам.
2. Прочитай целиком файлы темы: что код вызывает, кто его использует (Grep по имени экспорта), что он создаёт или читает снаружи (файлы, env, сеть).
3. Если есть `CLAUDE.md` или `docs/framework/` — сверься с ними, «почему так» бери оттуда и из комментариев в коде.
4. Ничего не додумывай: каждое утверждение опирается на код. Что нельзя подтвердить кодом — не утверждай.

## Шаг 2. Команды — только после одобрения

Код читается без вопросов. Любую команду (`git log`, `npx playwright test --list`, прогон тестов) можно запустить **только после явного одобрения**: назови команду и зачем она, дождись ответа. Без одобрения объясняй по коду.

Никогда не выводи содержимое `.env` и `playwright/.auth/*`.

## Шаг 3. Ответ в чат

Коротко: весь ответ — примерно полэкрана. Без построчного разбора, без цитат кода, без эмодзи. Русский язык, идентификаторы и пути — как в коде, в обратных кавычках. Ровно четыре блока в этом порядке, ничего сверх них:

1. **Суть** — два коротких абзаца:
   - описание, 3–4 предложения: что это, когда выполняется, что по шагам делает и что получается в результате;
   - **Зачем:** 1–2 предложения о смысле и значимости — какую проблему решает и что было бы без неё (медленнее, нестабильнее, дублирование и т.п.).
2. **Схема** — блок кода `text`, до ~10 строк: порядок выполнения и что создаётся/передаётся. Стрелки `→`, отступы для вложенности.
3. **Файлы** — таблица `Файл | Роль`, файл — ссылка `[path:line](path:line)` на ключевое место. Только главные файлы темы, обычно 3–6.
4. **Команды** — 1–2 самые базовые команды из `package.json` / `CLAUDE.md`, каждая в своём блоке `bash` с одной строкой пояснения перед ним. Команды предлагаются, а не запускаются.

Не добавляй подводные камни, замечания к коду, списки тем «что разобрать дальше», выводы и итоги.

## Шаг 4. Подробности — только если пользователь спросил

Если пользователь просит раскрыть конкретный момент — ответь только на него: по шагам, со ссылками `файл:строка`, короткая цитата кода только если без неё непонятно. Блоки обзора повторно не выводить.
