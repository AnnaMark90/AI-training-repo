## Проверка на false positive

Как убедились, что негативный тест падает на невалидных данных (что изменили, какой получили результат):

Мутации: временная копия спека `tests/store/zz-mutant.spec.ts` с одной испорченной строкой, прогон, копия удалена. Исходный файл не менялся.

| #   | Тест        | Что изменили                                                                    | Результат                                                               |
| --- | ----------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 1   | `TC-03-NEG` | Вместо одного `Black` выбраны `Black` + `M` (валидный вариант вместо неполного) | failed: `toBeDisabled()` — Expected: disabled, Received: enabled        |
| 2   | `TC-03-NEG` | После Black ожидается цена без `From`                                           | failed: `toHaveText` — Expected: "€10.00", Received: "From €10.00"      |
| 3   | `TC-03`     | Выбран только `Black`, без `M`                                                  | failed: `toBeEnabled()` — Expected: enabled, Received: disabled         |
| 4   | `TC-03`     | После выбора ожидается `From €10.00`                                            | failed: `toHaveText` — Expected: "From €10.00", Received: "€10.00"      |
| 5   | `TC-03`     | Ожидаемая цена `€11.00`                                                         | failed: `toHaveText` — Expected: "From €11.00", Received: "From €10.00" |

Вывод: оба теста падают, когда данные или поведение не совпадают с ожиданием; значения Received реальные, то есть локаторы находят элементы.

- [x] 2 прогона подряд без флака
- [x] `npm run lint` и `npm run typecheck` проходят

**Компромисс по локатору `priceLabel`.** Обёртка `From €10.00` не имеет `data-testid`, поэтому локатор — `this.container.locator('span').filter({ has: page.getByTestId('product-price') })`: тег `span`, привязанный к существующему test-id, без индексов и XPath. Это отступление от правила README «data-testid locators», в коде оставлен поясняющий комментарий. Запрос к разработке: добавить `data-testid` на обёртку цены, после чего перевести `priceLabel` на `getByTestId`.

Проверка на флак из-за ранних кликов до гидратации страницы: воспроизводится только искусственно (`goto` с `waitUntil: 'commit'` и клик сразу). В реальном тесте `goto` ждёт `load`, все прогоны выше зелёные.
