## 1. Вынести сводку из inline `node -e` в типизированный скрипт (P2-6)

**Сейчас.** 32 строки JS внутри YAML (строки 81–112). Скрипт не проверяют ни ESLint, ни `tsc`. Поэтому необъявленная `p`, несуществующие `stats.passed`/`stats.failed` и `t.title` прошли джобу `quality` незамеченными. Обнаружились они только в CI и только при заданных секретах. Эти три дефекта исправлены прямо в YAML, но новая правка скрипта несёт тот же риск.

**Предложение.** Перенести код в `scripts/ci-summary.ts` с типом `JSONReport` из `@playwright/test/reporter`. Логику оставить ту же, что сейчас в YAML: ключи `expected`/`unexpected`, итоговый `test.status`, название из `spec.title`.

Шаг будет выглядеть так:

```yaml
- name: Test summary
  if: ${{ !cancelled() && env.SESSION_URL != '' }}
  run: node scripts/ci-summary.ts test-results/results.json
```

**Обоснование.** `tsconfig.json` включает `**/*.ts`, а `eslint .` проверяет все файлы. Значит, ошибки такого рода поймает джоба `quality` ещё до e2e, а локально — `npm run typecheck`. Все три дефекта этого инцидента были бы видны как ошибки типов.

Скрипт запускается без `tsx`: Node начиная с 22.18 и 23.6 сам отбрасывает аннотации типов. Для этого нужен пункт 3.

## 2. Отделить отчётность от результата тестов (P2-5, P3-12)

**Сейчас.** Шаг `Test summary` влияет на статус джобы. Сейчас он проходит, но любая будущая ошибка в нём (например, битый JSON) снова сделает CI красным при зелёных тестах, как в инциденте 41614491572. Кроме того, при красной джобе не сохраняется кэш браузеров.

**Предложение.**

- Для `Test summary` задать `continue-on-error: true`: ошибка сводки даст аннотацию, но не повлияет на статус.
- Кэш разделить на `actions/cache/restore` и `actions/cache/save`, у `save` поставить `if: always()`. Ещё лучше — удалить кэш браузеров: попадание в кэш в 41640708191 и 41641845635 дало установку за 12 с и 20 с, промах в 41637887351 — 19 с.

**Обоснование.** Статус e2e-джобы должен означать «тесты прошли или упали». Иначе инциденты вроде этого отнимают время на разбор того, что тесты не ломали.

## 3. Зафиксировать версию Node (P3-10)

**Сейчас.** `node-version: lts/*` в строках 21 и 46 в CI разрешился в Node 26.13.0, локально стоит Node 24. В `package.json` нет поля `engines`, хотя Playwright требует Node `>=20`, а README пишет «Node 18+» (см. `docs/framework/03-issues.md:19`).

**Предложение.** Добавить `.nvmrc` (например, `24`), в обеих джобах указать `node-version-file: .nvmrc`, а в `package.json` добавить `"engines"`.

**Обоснование.** CI и локальная среда будут на одной версии, и выход новой LTS перестанет молча менять окружение. Это также нужно для пункта 1.

## 4. Не делать запуск зелёным, если e2e фактически не выполнялись (P1-4) — ⏸ отложено

Отложено по решению от 2026-11-03.

**Сейчас.** Без `SESSION_URL` джоба `e2e` пропускает все шаги и завершается со статусом `success`. Из-за этого push-запуск 41612322021 был зелёным, хотя дефект уже был в коде.

**Предложение.**

- При `workflow_dispatch` и в `main` отсутствие `SESSION_URL` должно давать ошибку (`exit 1` с той же подсказкой).
- В ветках без секретов оставить пропуск, но писать «e2e skipped» в `$GITHUB_STEP_SUMMARY`, чтобы пропуск был виден на странице запуска.

**Обоснование.** Ложно-зелёный статус скрывает дефекты в шагах, которые выполняются только при наличии стенда.

## 5. Обновить actions и сузить триггеры (P2-9, P2-8)

**Сейчас.**

- `actions/checkout@v4`, `setup-node@v4`, `cache@v4` и `upload-artifact@v4` работают на Node 20. Annotation во всех запусках: `Node.js 20 is deprecated ... forced to run on Node.js 24`.
- Триггер `push:` срабатывает на любую ветку.

**Предложение.**

- Перейти на актуальные мажорные версии actions.
- Триггеры: `push: branches: [main]`, `pull_request: branches: [main]`, `workflow_dispatch`.

**Обоснование.** Когда поддержку Node 20 окончательно уберут, v4 могут перестать работать. Узкие триггеры убирают лишние запуски на общий стенд с одной БД.

## 6. Проверить видимость репозитория (P1-3) — ⏸ отложено

Отложено по решению от 2026-11-03.

**Сейчас.** `AnnaMark90/AI-training-repo` — **публичный** форк (`gh repo view`: `visibility: PUBLIC`, `isFork: true`). `README.md:93` требует приватный репозиторий: «never a public fork». При падении теста трасса ретрая с cookie стенда попадает в публичный артефакт (подтверждено, см. P1-3 в 05).

**Предложение.** Решение за владельцем, YAML здесь не меняется. Создать приватную копию репозитория и перенести в неё секреты. Если репозиторий остаётся публичным — отключить трассы в CI.

**Обоснование.**

- Маскирование `***` действует только на логи, на артефакты оно не распространяется.
- Решения задания и логи CI видны всем.
- PR из чужих форков не получают секретов, поэтому e2e в них молча пропускаются (пункт 4).
