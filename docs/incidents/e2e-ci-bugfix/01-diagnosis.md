## Причина

Ошибка в inline-скрипте `node -e` шага `Test summary`. В коммите `063c6a5` («chore(ci): add broken workflow and Claude config files») из скрипта удалены две строки. До удаления они были в `9f15849`:

```js
const fs = require("fs");
const p = "test-results/results.json";
```

- Без `fs` скрипт продолжает работать: в режиме `node -e` встроенные модули доступны как глобальные переменные.
- Переменная `p` больше нигде не объявлена. Первая же строка `fs.existsSync(p)` бросает `ReferenceError`, `node` выходит с кодом 1, шаг и джоба становятся красными.

Воспроизведено локально (Node 24.13.1): тот же фрагмент даёт `ReferenceError: p is not defined` и `exit=1`. С двумя возвращёнными строками скрипт завершается с кодом 0.

### Дополнительные дефекты конфигурации в том же шаге

Эти дефекты были найдены при диагностике и не давали шагу работать правильно после возврата `p`. Все три закрыты, см. [`06-fixes.md`](06-fixes.md).

1. ✅ **Исправлено в `2feb9d8` (P1-1).** Строки 87–88 читали `stats.passed` и `stats.failed`, а в JSON-отчёте Playwright таких ключей нет. Там есть `expected`, `unexpected`, `flaky`, `skipped`, `duration` и `startTime`. Поэтому сводка всегда показывала `Passed: 0`, `Failed: 0`. Это подтвердил запуск 41637887351: `Passed: 0` при `7 passed`.
2. ✅ **Исправлено в `5107656` (P1-2).** Строка 104 `collectFailed` искала только попытки со статусом `failed`. Тесты со статусом `timedOut` в список не попадали, а flaky-тесты (упал, затем прошёл на ретрае) попадали в «Failed». Позже при проверке нашёлся третий дефект: строка 105 выводила `t.title`, а у объекта теста в JSON-отчёте такого поля нет. Вместо названия теста получалось `undefined`.
3. ✅ **Решено исправлением P0.** Из-за упавшего шага не сохранился кэш браузеров: у `Post Cache Playwright browsers` статус `skipped`, потому что `actions/cache` сохраняет кэш только при успешной джобе. В первом зелёном запуске 41637887351 кэш сохранился (`Cache saved with key: playwright-Linux-…`), а в следующих восстанавливался. При красной джобе кэш по-прежнему не сохраняется (P2-5 в [`05-config-issues.md`](05-config-issues.md)).
